# massage-booking-bot

Telegram-бот записи на массаж. Требования и принятые решения — в [AGENTS.md](AGENTS.md).

Сделан Этап 1: `/start`, главное меню, запись по свободным слотам, сохранение в БД.
Плюс просмотр и отмена своих записей. Google Calendar (Этап 2) и напоминания (Этап 5)
ещё не подключены, но схема БД и точки расширения под них уже есть.

## Запуск

```bash
npm install
cp .env.example .env        # заполнить BOT_TOKEN и ADMIN_TELEGRAM_ID

npm run db:up               # postgres в docker, если нет своего
npm run db:migrate          # применить миграции
npm run db:seed             # услуга и рабочие часы по умолчанию

npm run dev
```

`BOT_TOKEN` берётся у [@BotFather](https://t.me/BotFather), `ADMIN_TELEGRAM_ID` —
числовой id массажиста, его покажет [@userinfobot](https://t.me/userinfobot).

Если PostgreSQL уже стоит локально, docker не нужен — достаточно поправить
`DATABASE_URL` в `.env` и создать базу:

```bash
createdb massage_booking
```

## Проверки

```bash
npm run typecheck
npm run lint
npm test        # юнит-тесты, БД не нужна
npm run test:db # интеграционные тесты против настоящей базы
```

`npm run test:db` вынесен отдельно, потому что проверяет то, что нельзя проверить
в памяти: exclusion constraint, который и не даёт занять слот дважды.

## Как это устроено

```text
src/
  bot/            тонкий слой Telegram: хендлеры, клавиатуры, сцены, middleware
  modules/        бизнес-логика
    availability/ availability.ts — чистый расчёт слотов, ключевая функция проекта
    appointments/ создание и отмена записей
    schedule/     рабочие часы и исключения
  integrations/   место для Google Calendar (Этап 2)
  jobs/           место для напоминаний (Этап 5)
  db/             Prisma client с driver adapter
  config/         конфигурация, валидируется Zod при старте
```

Три вещи, вокруг которых собрано всё остальное:

**Двойное бронирование ловит база, а не код.** Проверка слота перед вставкой нужна
для понятного сообщения человеку, но гарантию даёт `appointment_no_overlap` —
exclusion constraint из миграции `20260904120000_init`. Ошибка `23P01`
превращается в «время только что заняли».

**У записи два конца.** `endAt` — конец сеанса, его видит клиент. `blockedUntil` —
конец занятости вместе с техническим перерывом, по нему считается пересечение.

**Расчёт слотов — чистая функция.** `availableSlots()` не ходит в БД и не смотрит
на системные часы: всё приходит аргументами. Поэтому её можно честно протестировать,
включая переход на летнее время.
